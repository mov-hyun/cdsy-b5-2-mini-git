## 실행

Python 3.10 이상. 외부 패키지 설치 없이 표준 라이브러리만 사용한다.

```sh
python main.py
```

```text
mini-git> init "Alice Kim"
Initialized repository.
Current branch: main
Current user: Alice Kim
mini-git> commit "Initial commit"
[main c000001] Initial commit
mini-git> branch feature
Created branch: feature
mini-git> switch feature
Switched to branch: feature
mini-git> commit "Add login feature"
[feature c000002] Add login feature
mini-git> switch main
Switched to branch: main
mini-git> commit "Add payment feature"
[main c000003] Add payment feature
mini-git> path c000002 c000003
Path: c000002->c000001->c000003
mini-git> quit
Goodbye.
```

`help`로 현재 구현한 명령을 확인한다. 공백이 포함된 작성자·메시지는 따옴표로 감싼다. 명령 이름만 대소문자를 무시하며, 작성자·메시지·브랜치 이름은 입력을 유지한다.

| `tests/` | 모델 동작, 잘못된 입력, 실제 CLI 실행 검증 |

`commits`는 `hash -> Commit`, `branches`는 `branch_name -> commit_hash` 형태의 dict다. 첫 커밋 전 브랜치 값은 `None`이다. `current_branch`가 HEAD의 브랜치 이름을 보관하고, `head` 속성이 그 브랜치의 끝 커밋 hash를 반환한다.

커밋은 hash, message, author, timestamp, parents를 가진다. 변경 불가능한 dataclass와 부모 tuple을 사용한다. 생성 시각은 시간대가 명시된 UTC다. hash는 세션 내 증가 카운터(`c000001`, `c000002`, ...)로 만들며, 6자리는 최소 숫자 폭이다. 숫자가 커져도 잘라내지 않는다.

예시 실행 후 부모 연결은 다음과 같다. 화살표는 자식에서 부모 방향이다.

```text
c000002 -> c000001 <- c000003
feature -> c000002
main    -> c000003
HEAD    -> main
```

일반 COMMIT은 이미 존재하는 현재 HEAD를 부모로 삼고, MERGE는 현재 브랜치와 대상 브랜치의 기존 끝 커밋을 부모로 삼는다. 기존 커밋의 부모는 바꾸지 않으므로 이 명령들로 순환을 만들 수 없다. 브랜치를 만들 때 커밋을 복사하지 않으며 현재 브랜치도 바뀌지 않는다. COMMIT과 MERGE는 현재 브랜치만 새 커밋으로 옮긴다.

## 현재 적용한 입력·상태 정책

- INIT 전 저장소 명령: `Repository not initialized`.
- 반복 INIT: `Repository already initialized`. 기존 이력을 보존한다.
- 비어 있거나 공백뿐인 작성자·메시지: `Invalid args`.
- 브랜치명: 공백 없는 비어 있지 않은 문자열. 중복 생성은 `Branch already exists: <name>`.
- 없는 브랜치 전환: `Unknown branch: <name>`.
- 없는 커밋 조회: `Unknown commit: <hash>`. PATH의 시작과 도착 모두 검사한다.
- 인자 개수 오류·닫히지 않은 따옴표: `Invalid args`.
- 알 수 없는 명령: `Unknown command: <name>`.
- 첫 커밋 전 브랜치 생성 허용. 각 빈 브랜치에서 첫 커밋을 만들면 서로 연결되지 않은 루트가 생긴다.
- exit / quit, EOF, 입력 대기 중 Ctrl+C로 종료한다.
- 메모리에서만 동작한다. 실제 파일 내용 추적, 원격 통신, 데이터 영속성은 구현하지 않는다.

## 2단계: 커밋 그래프 탐색

### LOG: 부모 우선 위상 정렬

전체 저장소의 모든 브랜치와 독립 루트를 포함한다. Kahn 알고리즘을 사용한다.

1. 각 커밋의 미출력 부모 수를 센다.
2. 부모가 없는 커밋을 대기열에 넣는다.
3. 대기열에서 커밋을 꺼내고, 자식의 미출력 부모 수를 줄인다.
4. 모든 부모가 출력된 자식을 대기열에 추가한다.

대기열은 list와 읽기 위치로 구현해 앞 원소 삭제 비용을 피한다. 가능한 위상 순서가 여럿이면 dict의 삽입 순서와 대기열 순서에 따른다. 정렬 API는 사용하지 않는다. 비어 있는 저장소는 `No commits`를 출력한다. 모델의 정상 동작으로 순환은 생기지 않지만, 그래프 함수는 순환 또는 없는 부모가 전달되면 오류를 낸다.

### PATH: BFS와 사전순 최단 경로

`PATH <start> <end>`는 부모 연결을 양방향으로 이동한다. 도착 커밋에서 BFS를 실행해 각 커밋의 도착점까지 최단 거리를 구한다. 시작 커밋부터 남은 거리가 1씩 감소하는 이웃 중 사전순으로 가장 앞서는 다음 토큰을 선택한다.

hash는 `c`와 숫자로 구성되어 `->`를 포함하지 않는다. 이 형식에서 `hash->` 토큰을 비교하면 처음 달라지는 토큰이 전체 경로 문자열의 사전순을 결정한다. 모든 최단 경로를 저장하거나 열거하지 않는다. 시작과 도착이 같으면 커밋 하나를 반환하고, 연결되지 않은 경우 `No path`를 출력한다.

```text
mini-git> path c000002 c000003
Path: c000002->c000001->c000003
mini-git> path c000001 c000001
Path: c000001
```

### ANCESTORS: 부모 방향 DFS

`ANCESTORS <hash>`는 부모 방향만 따라간다. 시작 커밋을 제외하고 모든 조상의 hash, author, timestamp, message를 출력한다. 방문 집합으로 공통 조상의 중복을 막으며, 스택을 사용해 재귀 깊이에 의존하지 않는다. 출력 순서는 탐색 순서이고 별도 정렬을 보장하지 않는다. 루트 커밋이면 `No ancestors`를 출력한다.

### 시간·공간복잡도

V는 전체 커밋 수, E는 부모 연결 수다. Va와 Ea는 시작 커밋 및 도달 가능한 조상 부분의 정점·간선 수다. 아래는 평균 O(1) 해시 조회와 식별자 비교를 가정한 알고리즘 비용이며, 출력 문자열의 길이 비용은 별도다.

| 기능 | 시간 | 보조 공간 | 이유 |
| --- | --- | --- | --- |
| LOG | O(V + E) | O(V + E) | 역방향 연결 구성과 Kahn 순회 |
| PATH | O(V + E) | O(V + E) | 무방향 연결 구성, BFS, 거리 감소 경로 복원 |
| ANCESTORS | O(Va + Ea) | O(Va) | 도달 가능한 부모만 탐색, 발견 시 방문 표시 |

PATH에서 hash 길이를 H로 따로 고려하면 토큰 비교에 최대 O(H)가 들며, 비교 비용은 최대 O(EH)가 추가된다.

## 3단계: 역색인 검색

커밋 생성 시 `InvertedIndex.add()`를 호출해 다음 두 인덱스를 함께 갱신한다.

```text
keyword -> commit_hash 목록
author  -> commit_hash 목록
```

메시지 `Add Login feature`는 `add`, `login`, `feature`로 저장한다. 공백 기준 `split()`과 소문자 정규화 `lower()`를 사용하며, 한 메시지의 반복 단어는 한 번만 등록한다. 각 목록은 커밋 생성 순서를 유지한다.

### 명령과 검색 정책

```text
SEARCH login
SEARCH "login feature"
SEARCH --author="Alice Kim"
```

- 단일 키워드는 정규화된 토큰과 정확히 일치해야 한다. `LOGIN`은 `login`과 같고, `log`는 `login`과 다르다.
- 구두점은 유지한다. 메시지의 `login,`은 `SEARCH "login,"`으로 찾는다.
- 공백이 있는 키워드는 모든 토큰이 포함된 커밋을 찾는 AND 검색이다. `"login feature"`와 `"feature login"`의 결과는 같다. 단어가 연속해 있을 필요는 없다. 여러 단어 처리 방식은 원문에 명시되지 않아 이 정책을 선택했다.
- 여러 토큰 검색은 가장 짧은 후보 목록을 순회하고, 나머지 후보를 set으로 만들어 포함 여부를 검사한다.
- 작성자 이름은 대소문자와 공백을 포함해 정확히 일치해야 한다. `Alice Kim`과 `alice kim`은 다르다.
- 명령 이름은 대소문자를 무시한다. 옵션 이름은 과제 문법에 맞춰 `--author=`로 고정하며, `--`로 시작하는 다른 인자는 `Invalid args`다.
- 검색은 전체 저장소를 대상으로 하며 모든 브랜치의 커밋을 포함한다. 결과는 커밋 생성 순서로 출력한다.
- 결과가 있으면 개수와 hash, author, timestamp, message를 출력한다. 결과가 없으면 `No commits`를 출력한다.
- 빈 키워드와 빈 작성자 값은 `Invalid args`다. 아직 INIT하지 않았다면 `Repository not initialized`다.

검색 함수는 인덱스에서 hash 목록을 받은 뒤 해당 hash로 커밋을 직접 조회한다. 검색할 때 전체 커밋이나 전체 메시지를 순회하지 않는다. 작성자 변경 명령은 과제에 없으므로 CLI에 추가하지 않았으며, 여러 작성자는 테스트 데이터로 검증한다.

### 검색 복잡도와 비용

M은 새 메시지의 문자 수, A는 작성자명의 문자 수, Q는 질의 문자 수, K는 결과 개수다. q는 서로 다른 질의 토큰 수, P는 해당 토큰들의 후보 목록 길이 합, m은 가장 짧은 후보 목록 길이다. dict/set 조회는 평균 O(1), 목록 추가는 분할 상환 O(1)로 계산한다. 결과 표시 문자열을 만드는 비용은 별도다.

| 작업 | 시간 | 설명 |
| --- | --- | --- |
| 커밋 인덱싱 | O(M + A) | 메시지 분리·정규화, 중복 제거, 두 인덱스에 추가 |
| 단일 키워드 검색 | O(Q + K) | 질의 정규화 후 후보 목록 조회·복사 |
| 작성자 검색 | O(A + K) | 작성자 키 조회 후 결과 목록 조회·복사 |
| 여러 키워드 검색 | O(Q + P + qm + K) | 후보 집합 구성, 최소 후보 목록의 교집합 검사 |

여러 키워드 검색의 추가 공간은 O(Q + P + K)다. 인덱스에는 커밋마다 작성자 연결 1개와 중복을 제거한 메시지 토큰 수만큼의 연결을 저장하므로, 검색을 빠르게 하는 대신 메모리와 커밋 생성 시 갱신 비용이 든다. 모든 커밋이 검색에 일치하면 결과 출력에도 전체 결과 개수만큼 시간이 필요하다.

## 4단계: 직접 구현한 정렬

```text
LOG --sort-by=date
LOG --sort-by=author
```

- `date`: timestamp 오름차순, 즉 오래된 시각부터 출력한다.
- `author`: 작성자 문자열을 대소문자를 구분하는 유니코드 순서로 출력한다. 예를 들어 `A`, `Z`, `a`, `가` 순서다.
- 두 옵션 모두 같은 값의 커밋은 생성 순서를 유지한다.
- 옵션을 지정하면 해당 정렬 기준을 적용한다. 기본 `LOG`에 적용하는 부모 우선 조건은 정렬 옵션과 별개다.
- `--sort-by=date|author`는 두 선택지를 표현한 문법 표기다. 실제 입력에서는 `date` 또는 `author` 하나를 선택한다.
- 빈 저장소는 `No commits`, 잘못된 정렬 옵션은 `Invalid args`다.

### 병합 정렬의 동작과 안정성

`sorting.py`의 `merge_sort(items, key)`는 입력 목록을 변경하지 않고 정렬된 새 목록을 반환한다. `key` 함수로 날짜·작성자 등 비교 기준을 바꾸며, 각 항목의 키를 한 번 계산해 재사용한다.

1. 길이 1인 각 구간은 이미 정렬되어 있다.
2. 인접한 두 구간의 앞쪽 키를 비교해 작은 항목부터 새 버퍼에 쓴다.
3. 두 키가 같으면 왼쪽 구간의 항목을 먼저 쓴다.
4. 구간 길이를 1, 2, 4, 8, ...로 늘려 전체 목록을 병합한다.

왼쪽 구간은 원래 입력에서 먼저 등장한 구간이다. 동률에서 왼쪽을 먼저 선택하고 각 구간 내부 순서를 유지하므로 전체 정렬도 안정적이다. 재귀 호출 없이 반복문과 두 버퍼로 처리한다.

커밋 수를 n이라고 하면 병합 단계는 약 log₂n개이며, 각 단계는 n개 항목을 처리한다. 최선·평균·최악 시간복잡도는 모두 O(n log n), 보조 공간은 O(n)이다(n이 0 또는 1이면 상수 시간). 키 비교 비용이 상수라는 가정이며, 작성자 문자열 비교에는 문자열 길이에 따른 추가 비용이 든다. 날짜·작성자 정렬은 그래프나 브랜치, 검색 인덱스를 변경하지 않는다.

## 보너스: 두 부모를 갖는 MERGE

`MERGE <branch_name>`은 현재 브랜치의 HEAD와 대상 브랜치의 HEAD를 부모로 하는 새 커밋을 만든다. 부모 순서는 `(현재 HEAD, 대상 HEAD)`이며, 작성자는 현재 사용자, 메시지는 `Merge branch '<target>' into '<current>'`다. 현재 브랜치만 새 커밋으로 이동하고 대상 브랜치는 유지한다.

새로 실행한 프로그램에서 다음 순서로 확인할 수 있다.

```text
init Alice
commit "Initial commit"
branch feature
switch feature
commit "Add login feature"
switch main
commit "Add payment feature"
merge feature
log
ancestors c000004
path c000004 c000001
search merge
```

생성되는 부모 연결은 다음 두 경로를 공유한다.

```text
c000004 -> c000003 -> c000001
c000004 -> c000002 -> c000001

main    -> c000004
feature -> c000002
```

`ANCESTORS c000004`는 c000001, c000002, c000003을 각각 한 번 출력한다. `PATH c000004 c000001`은 두 최단 경로 중 사전순으로 앞서는 `c000004->c000002->c000001`을 선택한다.

병합 커밋도 일반 커밋과 같은 내부 생성 함수를 사용하므로 hash 발급, 생성 시각 기록, 두 역색인 갱신이 함께 이루어진다. 이후 일반 COMMIT을 만들면 병합 커밋 하나를 부모로 삼는다. 부모 연결 갱신은 평균 O(1), 자동 메시지와 작성자 인덱싱을 포함한 시간은 메시지 길이 M과 작성자 길이 A에 대해 O(M + A)다.

### 병합 정책

- 없는 브랜치: `Unknown branch: <name>`.
- 현재 브랜치 자신: `Cannot merge current branch`.
- 현재 또는 대상 브랜치에 커밋이 없는 경우: `Cannot merge empty branch: <name>`.
- 서로 다른 브랜치가 같은 커밋을 가리키는 경우: `Branches point to same commit`.
- 서로 다른 두 끝 커밋이 있으면 항상 두 부모를 갖는 새 커밋을 만든다. 한쪽이 다른 쪽의 조상인 경우에도 이 규칙을 적용한다.
- 독립 루트가 있는 브랜치도 두 부모 연결로 병합할 수 있다.
- 실패한 병합은 커밋·브랜치·인덱스 상태와 다음 hash 번호를 유지한다.

이 보너스는 커밋 메타데이터와 그래프 연결을 병합한다. 실제 파일 내용 결합, 충돌 해결, fast-forward 최적화는 구현하지 않는다.

## 보너스: 줄 단위 DIFF

`DIFF <file1> <file2>`는 첫 번째 파일에서 두 번째 파일로 바뀌는 내용을 출력한다. INIT 전에도 사용할 수 있으며 파일과 저장소 상태를 변경하지 않는다.

저장소 루트에서 프로그램을 실행한 뒤 제공한 예제를 비교한다.

```text
mini-git> diff examples/before.txt examples/after.txt
  Mini Git
- Basic commands
+ Indexed search
  Graph traversal
+ Stable sorting
```

각 줄은 표시 문자와 구분 공백으로 시작한다. `- `는 첫 번째 파일에서 삭제된 줄, `+ `는 두 번째 파일에 추가된 줄, 공백 두 개는 공통 줄이다. 동일한 두 파일은 모든 줄을 공통으로 출력하며, 둘 다 비어 있으면 `No lines`를 출력한다. 내용이 빈 줄도 표시 문자를 통해 구분할 수 있다.

### LCS 알고리즘

두 파일의 줄 목록에서 순서를 유지하는 가장 긴 공통 부분 수열(Longest Common Subsequence)을 찾는다. `diffing.py`에서 동적 계획법으로 직접 구현했다.

1. `lengths[i][j]`는 첫 파일의 i번째 줄 이후와 둘째 파일의 j번째 줄 이후에서 얻을 수 있는 LCS 길이다.
2. 두 줄이 같으면 대각선 다음 값에 1을 더한다.
3. 다르면 첫 파일의 줄을 건너뛴 경우와 둘째 파일의 줄을 건너뛴 경우 중 큰 값을 사용한다.
4. 표를 따라 공통·삭제·추가 줄을 복원한다. 선택이 동률이면 삭제를 먼저 출력한다.

두 파일의 줄 수가 n, m이고 LCS 길이가 L이면 추가·삭제의 최소 합계는 `n + m - 2L`이다. 줄 교체는 삭제 1개와 추가 1개로 표현한다. 반복되는 줄이 있어도 결정된 동률 규칙에 따라 일관된 결과를 낸다.

DP 시간·공간은 두 입력이 비어 있지 않을 때 O(nm), 빈 입력과 경계까지 포함하면 O((n+1)(m+1))이다. 결과 복원은 O(n+m)이며 파일 읽기와 문자열 비교 비용은 별도다. 두 파일의 줄 수 곱만큼 표를 만들므로 작은 텍스트 파일 비교를 위한 구현이다.

### 파일 및 경로 정책

- UTF-8 텍스트를 읽으며 UTF-8 BOM은 허용한다. 다른 인코딩은 자동 추정하지 않는다.
- 줄바꿈 문자는 비교에서 제외한다. LF/CRLF 차이와 마지막 줄의 개행 유무는 같은 내용으로 취급한다.
- 줄 내부의 공백·탭·대소문자는 그대로 비교한다. 빈 줄도 비교 대상이다.
- 상대 경로는 프로그램을 실행한 폴더를 기준으로 한다. 절대 경로도 사용할 수 있다.
- 공백이 있는 경로는 따옴표로 감싼다. 예: `diff "old file.txt" "new file.txt"`.
- DIFF 인자의 역슬래시는 이스케이프로 해석하지 않아 Windows 경로를 그대로 전달한다. 다른 명령의 기존 따옴표·이스케이프 처리는 유지한다.
- 없는 파일: `File not found: <path>`, 디렉터리: `Not a file: <path>`.
- UTF-8 해석 실패: `Invalid UTF-8 file: <path>`, 그 밖의 읽기 오류: `Cannot read file: <path>`.
- 인자 개수 오류·빈 경로·닫히지 않은 따옴표: `Invalid args`. 오류 후에도 다음 명령을 입력할 수 있다.

## 보너스: 두 정렬 알고리즘 성능 비교

`sorting.py`에 삽입 정렬을 추가했다. 정렬된 앞부분에서 현재 항목보다 큰 키를 오른쪽으로 밀고, 빈 위치에 현재 항목을 넣는다. 같은 키는 이동시키지 않아 안정적이다. 두 알고리즘 모두 원본을 보존하고, 비교 키를 항목당 한 번 계산한다. 실제 `LOG --sort-by=...`는 병합 정렬을 사용한다.

| 알고리즘 | 최선 시간 | 평균 시간 | 최악 시간 | 보조 공간 | 안정성 |
| --- | --- | --- | --- | --- | --- |
| 병합 정렬 | O(n log n) | O(n log n) | O(n log n) | O(n) | 안정 |
| 삽입 정렬 | O(n) | O(n²) | O(n²) | O(n) | 안정 |

이 삽입 정렬 구현은 입력 복사와 키 캐시를 사용하므로 보조 공간이 O(n)이다. 이미 정렬된 입력에서는 각 항목이 제자리에 들어가 O(n), 역순에서는 앞의 항목들을 계속 밀어 O(n²)이 된다. 병합 정렬은 정렬 여부와 관계없이 각 병합 단계를 수행한다.

### 재현 방법과 측정 조건

저장소 루트의 터미널에서 실행한다. Mini Git REPL 내부 명령은 아니다.

```sh
python benchmark_sorts.py --sizes 100 500 1000 2000 4000 --repeats 5
```

- 입력 유형: 0~n-1의 무작위 순열, 오름차순, 역순, 0~7의 중복 정수.
- 입력 크기: 100, 500, 1,000, 2,000, 4,000. 유형·크기 조합마다 두 알고리즘에 동일한 목록을 제공한다.
- 기본 seed는 20261004이며 각 입력 생성에는 `seed + size`를 사용한다.
- 각 알고리즘·입력 조합을 한 번 예열하고 5회 측정한다. 총 200회 측정하며 실행 순서를 번갈아 배치한다.
- `perf_counter_ns()`로 정렬 호출을 측정한다. 입력 복사·키 계산·정렬을 포함하고, 입력 생성·결과 검증·출력은 제외한다.
- 매 실행 뒤 오름차순, 원소 보존, 원본 불변성을 확인한다. 표의 값은 5회 산술평균이다.
- [전체 측정표](benchmarks/sort_results.md)와 [원시 표본 JSON](benchmarks/sort_results.json)에 환경·설정·측정값을 저장한다.
- 기본 실행은 위 두 결과 파일을 갱신한다. 이전 결과를 별도로 보관하려면 `--output benchmarks/another_run.json`처럼 새 파일명을 지정한다.
